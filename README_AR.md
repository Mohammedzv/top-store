# TOP STORE PRO — دليل التشغيل والرفع

المشروع يحتوي على متجر عربي RTL، وسلة مشتريات، وإرسال طلبات، ولوحة إدارة منفصلة للمنتجات والطلبات، باستخدام Firebase Realtime Database وFirebase Authentication، ومناسب للنشر على GitHub Pages.

## 1) إعداد Firebase

1. افتح https://console.firebase.google.com وأنشئ مشروع Firebase.
2. من Project settings > General > Your apps، أنشئ Web App وانسخ إعدادات Firebase.
3. افتح `assets/firebase-config.js` واستبدل القيم التجريبية بالقيم الحقيقية. تأكد من `databaseURL`؛ رابط Realtime Database غالبًا بالشكل `https://PROJECT_ID-default-rtdb.firebaseio.com` أو النطاق الذي يعرضه Firebase عند إنشاء القاعدة.
4. من Build > Realtime Database أنشئ قاعدة بيانات.
5. من Build > Authentication > Sign-in method فعّل Email/Password.
6. من Authentication > Users أنشئ حسابًا إداريًا ببريد وكلمة مرور قوية. لا يوجد إنشاء حسابات عامة من صفحة الموقع.
7. انسخ UID الخاص بحساب الإدارة من صفحة Users.
8. من Realtime Database > Data، أضف مسارًا جديدًا:
   - Key: `admins`
   - داخلها أضف Key يساوي UID الحساب حرفيًا
   - Value: `true`
   مثال توضيحي: `admins / ABC123_UID / true`
   لا تضع البريد الإلكتروني بدل UID. قواعد قاعدة البيانات تمنع تعديل `admins` من المتصفح.
9. افتح تبويب Rules في Realtime Database وانشر محتوى `database.rules.json` الموجود مع المشروع. لا تستخدم قواعد الاختبار العامة أو قواعد تسمح بالكتابة للجميع.

## 2) نشر المشروع على GitHub Pages

1. ارفع كل محتويات مجلد المشروع إلى جذر مستودع GitHub، مع الحفاظ على مجلد `assets`.
2. من Settings > Pages اختر النشر من الفرع الرئيسي (عادة `main`) ومن المجلد `/ (root)`.
3. انتظر رابط الموقع. صفحة المتجر هي `https://USERNAME.github.io/REPOSITORY/` وصفحة الإدارة `https://USERNAME.github.io/REPOSITORY/admin.html`.
4. في Firebase Authentication > Settings > Authorized domains أضف نطاق GitHub Pages المستخدم إذا لم يكن موجودًا.
5. جرّب الموقع عبر رابط GitHub Pages أو خادم محلي. بعض المتصفحات لا تشغّل JavaScript modules عند فتح الملف مباشرة بصيغة `file://`.

## 3) إضافة المنتجات وإدارتها

- افتح `admin.html` وسجّل الدخول بالحساب الإداري.
- أضف الاسم والسعر والقسم ورابط صورة يبدأ بـ `https://` أو `http://`، ووصفًا اختياريًا.
- فعّل «نشر المنتج فور الحفظ» ليظهر في المتجر. إلغاء التفعيل يحفظه كمسودة مخفية.
- تستطيع تعديل المنتج أو إخفاءه أو نشره أو حذفه من الجدول.
- يجب أن يكون رابط الصورة رابطًا مباشرًا للصورة. هذا الإصدار لا يرفع ملفات الصور إلى Firebase Storage؛ يستخدم روابط الصور لتجنب تحميل صور كبيرة داخل قاعدة البيانات.

## 4) الطلبات

- يضيف الزبون المنتجات للسلة؛ السلة محفوظة محليًا على جهازه.
- عند إرسال الطلب تُحفظ بيانات العميل والمنتجات والإجمالي في المسار `orders`.
- تستطيع الإدارة مراجعة الطلبات وتغيير حالتها.
- هذا إصدار أساسي لبدء التشغيل. قبل الاستخدام التجاري الفعلي، أضف حماية إضافية ضد الرسائل المزعجة/الطلبات الآلية (مثل App Check أو طبقة خادم/Cloud Functions)، وسياسة خصوصية، وتحققًا من الأسعار والكميات على الخادم. لا تعتمد على السعر المرسل من المتصفح وحده لتأكيد فاتورة نهائية.

## 5) هيكل الملفات

- `index.html` — المتجر العام.
- `admin.html` — لوحة الإدارة.
- `assets/style.css` — التصميم المتجاوب.
- `assets/firebase-config.js` — إعدادات مشروعك.
- `assets/firebase.js` — تهيئة Firebase.
- `assets/store.js` — عرض المنتجات والسلة وإرسال الطلبات.
- `assets/admin.js` — تسجيل الإدارة وإدارة المنتجات والطلبات.
- `database.rules.json` — قواعد أمان Realtime Database.

## ملاحظات أمان مهمة

- بيانات `firebaseConfig` الخاصة بتطبيق الويب ليست كلمة مرور؛ الحماية الحقيقية من قواعد Firebase.
- لا تضع كلمة مرور حساب الإدارة داخل ملفات المشروع.
- لا تسمح للمتصفح بكتابة `admins`، ولا تنشر قواعد `.write: true`.
- إعدادات القواعد تسمح للزوار بقراءة `publicProducts` فقط، بينما مسار `products` والطلبات محميان للإدارة.
- الطلبات عامة للإنشاء فقط مع تحقق أساسي من الحقول، ولا يستطيع الزائر قراءتها أو تعديلها أو حذفها. ومع ذلك، يمكن لأي شخص محاولة إرسال طلبات مزيفة؛ طبّق حماية ضد الإساءة قبل إطلاق واسع.
